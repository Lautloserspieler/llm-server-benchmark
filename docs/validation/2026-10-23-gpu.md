# Local GPU validation — 2026-10-23

## Deutsch

Dieses technische Prüfprotokoll dokumentiert Funktionstests auf einer RTX 5070 mit Ollama, vLLM und TGI. Ollama und vLLM bestanden Generierung, Kontextprüfung und TTFT-Stresstests. TGI scheiterte während des GPU-Warmups und ist auf dieser Hardware nicht als funktionsfähig validiert. Die angegebenen Latenzen sind keine vergleichbaren Leistungsbenchmarks. Bei Ollama wurde eine stille Prompt-Kürzung erkannt und durch `truncate: false` und `shift: false` für die Kontextprobe korrigiert. Intel-GPU-Telemetrie konnte mangels passender Hardware nur über Tests mit simulierten Antworten geprüft werden.

## English

Validated on Windows/WSL2 with an NVIDIA GeForce RTX 5070 (12 GB), NVIDIA driver 621.01 and Docker Engine 29.8.2. The project is 1.6.5; the runtime correction is commit `bc73100`.

These are functional smoke tests on an active desktop, not controlled performance comparisons or a search for the maximum physical VRAM limit. No Intel GPU was available to validate xpu-smi on hardware.

## Correction found by the real GPU test

With Ollama 0.40.9, a 4,173-token prompt at `num_ctx=1024` was silently reduced to 514 tokens. The previous check only detected counts close to the full context window and incorrectly returned success.

The HTTP capacity probe now requests `truncate: false` and `shift: false`. The same real-server test then returned an HTTP context error, and a regression test covers the half-window behavior. See Ollama's request handling in [llama_server.go](https://github.com/ollama/ollama/blob/main/llm/llama_server.go).

Validation of the correction:

- Windows: 82 HTTP-probe tests passed.
- Linux Docker / Python 3.12: 981 passed, 17 skipped; Ruff and mypy passed (70 source files).

## RAM incident and cleanup

Pulling and unpacking the large CUDA runtime images grew the Docker/WSL guest file cache to approximately 42 GiB. `vmmemWSL` occupied 46.7 GiB and Windows had only 2 GiB free out of 63.9 GiB RAM. The TGI launch was stopped while this was investigated.

After stopping the test processes and clearing the guest file cache following `sync`, WSL working memory fell to 2.8 GiB. Windows returned to 35.5% RAM usage with 41.3 GiB free. The final TGI attempt was then restricted to 8 GiB and its failed container was removed. The guest file cache was cleared again after cleanup.

The user's `benchmark.yaml` was preserved. Downloaded images and models remain in the local caches for reuse.
