# v1.7.0 qualification protocol

## Deutsch

Dieses Dokument legt fest, welche Nachweise für das Release v1.7.0 (Issues #116, #120 bis #124) vorliegen müssen, und trennt sauber, was die automatische Testsuite belegt und was nur echte Hardware belegen kann. Kein Eintrag darf ohne Messprotokoll abgehakt werden; nicht getestete Hardwarekombinationen werden nicht als validiert beworben.

**Von der Testsuite belegt (CI, ohne Hardware):** Fehlerklassifikation der HTTP-Probes (`out_of_memory`, `context_exceeded`, `context_truncated`, `timeout`, `connection_error`, `invalid_response`, `startup_failed`), Start/Stopp-Zyklen mit Aufräumprüfung gegen simuliertes Docker, Startfehler-Taxonomie (`model_not_found`, `invalid_configuration`, `out_of_memory`, `startup_timeout`, `container_exited`, `interrupted`), Telemetrie-Mockfälle je Hersteller, stabile Geräteposition bei Ausfall, Coverage-Gates.

**Nur auf echter Hardware belegbar (offen, siehe Nachweisliste):**

1. Start/Stopp: 10 Zyklen je Backend mit demselben Referenzmodell, 10/10 ohne verwaiste Container.

   ```bash
   python scripts/smoke_all_backends.py --backends ollama vllm --cycles 10 --device gpu --output results/qualification/cycles
   ```

2. Ollama: mindestens zwei gepinnte Serverversionen, Kontextgrößen 1024/4096/8192, CPU-only und NVIDIA-GPU; ein sonst still gekürzter Prompt darf nie als verifiziert gelten.
3. Telemetrie: echte Traces je verfügbarer NVIDIA-/AMD-/Intel-Hardware. Fehlende Hersteller werden ausdrücklich als „nicht getestet“ eingetragen.
4. Linux und Windows (Docker Desktop/WSL2) gemäß CI-Matrix Python 3.10/3.12/3.14.
5. 8-Stunden-Soak auf der Referenzhardware:

   ```bash
   # benchmark.yaml: soak.duration_long_seconds: 28800
   llmbench run --config benchmark.yaml --hardware both --duration long
   ```

   Zu prüfen: kein Abbruch, kein Throttling-Hinweis, Telemetrie-Vollständigkeit (`sample_completeness`) und Sampler-Overhead (`sampling`) im Ergebnis, nach dem Lauf keine eigenen Container.

**TGI (#120):** Das Prüfprotokoll [2026-10-23-gpu.md](2026-10-23-gpu.md) dokumentiert, dass TGI 3.3.6 auf einer RTX 5070 beim GPU-Warmup abstürzt. Solange kein Lauf auf kompatibler Hardware gelingt, gilt TGI nicht als validiert. Issue #167 sieht die Ablösung durch SGLang vor; die Entscheidung muss vor dem Release feststehen.

### Bei der Qualifikation gefundene Einschränkungen

- **Soak mit Container-Backends:** Mit Ollama schlägt der Soak fehl (`llama-server wurde nicht bereit`), mit llama.cpp läuft er. Vermutete Ursache (nicht diagnostiziert): Beide Server teilen sich einen Containernamen. Der Soak gilt daher nur für llama.cpp als belegt.
- **CUDA nicht belegt:** llama.cpp lief als Vulkan-Build; ein CUDA-Nachweis steht aus.
- **Effizienzwerte der CPU-Profile** beziehen sich nur auf die gemessene GPU-Leistung (Messumfang `gpu:0`), weil die CPU-Leistung nicht verfügbar ist. Sie sind nicht mit GPU-Profilen vergleichbar.
- **Sampler:** Eine Messung dauert Ø 88 ms (rund 15 % des Intervalls); das tatsächliche Intervall liegt dadurch bei etwa 0,59 s.

## English

This document defines which evidence must exist for the v1.7.0 release (issues #116 and #120 to #124), and separates what the automated test suite proves from what only real hardware can prove. No item may be ticked without a measurement record; hardware combinations that were not tested are not advertised as validated.

**Proven by the test suite (CI, no hardware):** failure classification of the HTTP probes (`out_of_memory`, `context_exceeded`, `context_truncated`, `timeout`, `connection_error`, `invalid_response`, `startup_failed`), start/stop cycles with cleanup checks against simulated Docker, the startup failure taxonomy (`model_not_found`, `invalid_configuration`, `out_of_memory`, `startup_timeout`, `container_exited`, `interrupted`), mocked telemetry cases per vendor, stable device positions on failure, and the coverage gates.

**Provable only on real hardware (open, see the evidence list):**

1. Start/stop: 10 cycles per backend with the same reference model, 10/10 without orphaned containers.

   ```bash
   python scripts/smoke_all_backends.py --backends ollama vllm --cycles 10 --device gpu --output results/qualification/cycles
   ```

2. Ollama: at least two pinned server versions, context sizes 1024/4096/8192, CPU-only and NVIDIA GPU; a prompt that would otherwise be silently truncated must never count as verified.
3. Telemetry: real traces for each available NVIDIA/AMD/Intel device. Missing vendors are entered explicitly as "not tested".
4. Linux and Windows (Docker Desktop/WSL2) following the CI matrix Python 3.10/3.12/3.14.
5. 8-hour soak on the reference hardware:

   ```bash
   # benchmark.yaml: soak.duration_long_seconds: 28800
   llmbench run --config benchmark.yaml --hardware both --duration long
   ```

   Check: no abort, no throttling warning, telemetry completeness (`sample_completeness`) and sampler overhead (`sampling`) in the result, and no owned containers left afterwards.

**TGI (#120):** The validation record [2026-10-23-gpu.md](2026-10-23-gpu.md) documents that TGI 3.3.6 crashes during GPU warmup on an RTX 5070. Until a run succeeds on compatible hardware, TGI is not considered validated. Issue #167 proposes replacing it with SGLang; that decision must be settled before the release.

### Limitations found during qualification

- **Soak with container backends:** With Ollama the soak fails (`llama-server wurde nicht bereit`), with llama.cpp it runs. Suspected cause (not diagnosed): both servers share one container name. The soak is therefore only proven for llama.cpp.
- **CUDA not proven:** llama.cpp ran as a Vulkan build; a CUDA proof is still missing.
- **Efficiency values of CPU profiles** only reflect the measured GPU power (scope `gpu:0`) because CPU power is not available. They are not comparable with GPU profiles.
- **Sampler:** One measurement takes 88 ms on average (about 15% of the interval), so the real interval is about 0.59 s.
