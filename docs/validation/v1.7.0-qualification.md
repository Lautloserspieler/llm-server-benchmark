# v1.7.0 qualification protocol

## Deutsch

Dieses Dokument legt fest, welche Nachweise für das Release v1.7.0 (Issues #116, #120 bis #124) vorliegen müssen, und trennt sauber, was die automatische Testsuite belegt und was nur echte Hardware belegen kann. Kein Eintrag darf ohne Messprotokoll abgehakt werden; nicht getestete Hardwarekombinationen werden nicht als validiert beworben.

### Stand und offene Freigaben (13. November 2026)

Referenz: `main` nach [PR #183](https://github.com/Lautloserspieler/llm-server-benchmark/pull/183)
(`58a3230`), Projektversion weiterhin **1.6.5**. 1.7.0 ist noch nicht freigegeben.
Die [CI von #183](https://github.com/Lautloserspieler/llm-server-benchmark/actions/runs/43395578734)
belegt Windows-/Linux-Laufzeittests mit Python 3.10/3.12/3.14, mypy auf beiden
Systemen mit Python 3.12, Ruff, Coverage und saubere Wheel-/CLI-Installationen.
Die lokalen Tests zu diesem Stand ergaben 1449 bestanden, 15 uebersprungen und
81,64 % Gesamtabdeckung; die Gates von 75 % gesamt und 85 % Branch-Coverage in
allen zehn kritischen Modulen wurden erfuellt. [PR #182](https://github.com/Lautloserspieler/llm-server-benchmark/pull/182)
behebt ausserdem Community-Export und Apple-Silicon-Diagnose. Diese automatisierten
Nachweise ersetzen keine der unten geforderten Hardwaremessungen.

Die folgenden GitHub-Issues sind am Stichtag noch offen. Die Tabelle gleicht ihren
Inhalt mit dem Implementierungsstand und Entscheidung #167 ab; sie aendert keinen
GitHub-Status und bestaetigt keine vollstaendige Issue-Abnahme.

SGLang ist kein 1.7.0-Release-Blocker und noch nicht als Backend auswaehlbar.

**Von der Testsuite belegt (CI, ohne Hardware):** Fehlerklassifikation der HTTP-Probes (`out_of_memory`, `context_exceeded`, `context_truncated`, `timeout`, `connection_error`, `invalid_response`, `startup_failed`), Start/Stopp-Zyklen mit Aufräumprüfung gegen simuliertes Docker, Startfehler-Taxonomie (`model_not_found`, `invalid_configuration`, `out_of_memory`, `startup_timeout`, `container_exited`, `interrupted`), Telemetrie-Mockfälle je Hersteller, stabile Geräteposition bei Ausfall, Coverage-Gates.

**Nur auf echter Hardware belegbar (offen, siehe Nachweisliste):**

1. Start/Stopp: 10 Zyklen je aktivem Backend mit unveraenderter Referenzmodell-Identitaet innerhalb der Zyklen, 10/10 ohne verwaiste Container.

   ```bash
   python scripts/smoke_all_backends.py --backends llama_cpp ollama vllm --cycles 10 --device gpu --output results/qualification/cycles
   ```

   Der Smoke-Test nutzt backend-spezifische Standardmodelle. Fuer die Abnahme
   Modellrevision/-hash, Image-Digest und tatsaechliche GPU-API mit den Artefakten
   sichern; ein gruener Smoke allein belegt weder Pins noch CUDA. Jeder neue Lauf
   braucht ein eigenes Ausgabeverzeichnis, damit alte Nachweise erhalten bleiben.

2. Ollama: mindestens zwei gepinnte Serverversionen, Kontextgrößen 1024/4096/8192, CPU-only und NVIDIA-GPU; ein sonst still gekürzter Prompt darf nie als verifiziert gelten.
3. Telemetrie: echte Traces je verfügbarer NVIDIA-/AMD-/Intel-Hardware. Fehlende Hersteller werden ausdrücklich als „nicht getestet“ eingetragen.
4. Linux und Windows (Docker Desktop/WSL2) gemäß CI-Matrix Python 3.10/3.12/3.14.
5. 8-Stunden-Soak auf der Referenzhardware:

   ```bash
   # benchmark.yaml: soak.duration_long_seconds: 28800
   llmbench run --config benchmark.yaml --hardware both --duration long
   ```

   Zu prüfen: kein Abbruch, kein Throttling-Hinweis, Telemetrie-Vollständigkeit (`sample_completeness`) und Sampler-Overhead (`sampling`) im Ergebnis, nach dem Lauf keine eigenen Container.

6. Fuenf unabhaengige Wiederholungen eines identischen Referenzworkloads mit
   Einzelresultaten und dokumentierter Streuung gemaess #124. Keine absolute
   Tokens/s-Schwelle zwischen unterschiedlichen Engines erfinden.

**TGI (#120):** Entschieden: TGI wird eingestellt und durch SGLang ersetzt (siehe #167). Die Hardwarevalidierung aus #120 entfällt damit für 1.7.0. Hintergrund: Das Prüfprotokoll [2026-10-23-gpu.md](2026-10-23-gpu.md) dokumentiert, dass TGI 3.3.6 auf einer RTX 5070 beim GPU-Warmup abstürzt. Bis zur Entfernung (geplant 1.8.0) gilt TGI als nicht validiert.

### Bei der Qualifikation gefundene Einschränkungen

- **Soak mit Container-Backends:** Mit Ollama schlägt der Soak fehl (`llama-server wurde nicht bereit`), mit llama.cpp läuft er. Ursache laut Architekturvertrag: Container-Backends verwalten genau einen Container (Capability `multi_model`). Der Soak wird für sie jetzt mit klarer Meldung übersprungen und gilt nur für llama.cpp als belegt.
- **CUDA nicht belegt:** llama.cpp lief als Vulkan-Build; ein CUDA-Nachweis steht aus.
- **Effizienzwerte der CPU-Profile** beziehen sich nur auf die gemessene GPU-Leistung (Messumfang `gpu:0`), weil die CPU-Leistung nicht verfügbar ist. Sie sind nicht mit GPU-Profilen vergleichbar.
- **Sampler:** Eine Messung dauert Ø 88 ms (rund 15 % des Intervalls); das tatsächliche Intervall liegt dadurch bei etwa 0,59 s.

## English

This document defines which evidence must exist for the v1.7.0 release (issues #116 and #120 to #124), and separates what the automated test suite proves from what only real hardware can prove. No item may be ticked without a measurement record; hardware combinations that were not tested are not advertised as validated.

### Status and open acceptance items (13 November 2026)

Reference: `main` after [PR #183](https://github.com/Lautloserspieler/llm-server-benchmark/pull/183)
(`58a3230`), project version still **1.6.5**. 1.7.0 has not been accepted for release.
The [#183 CI run](https://github.com/Lautloserspieler/llm-server-benchmark/actions/runs/43395578734)
covers Windows/Linux runtime tests with Python 3.10/3.12/3.14, mypy on both systems
with Python 3.12, Ruff, coverage, and clean wheel/CLI installations. Local tests
at this state recorded 1449 passed, 15 skipped, and 81.64% total coverage; the 75%
overall gate and 85% branch gates for all ten critical modules passed.
[PR #182](https://github.com/Lautloserspieler/llm-server-benchmark/pull/182) also fixes
community export and Apple Silicon diagnostics. These automated checks do not
replace any of the real-hardware measurements required below.

reconciles their contents with the implementation and decision #167; it does not
change GitHub state or establish complete issue acceptance.

**Proven by the test suite (CI, no hardware):** failure classification of the HTTP probes (`out_of_memory`, `context_exceeded`, `context_truncated`, `timeout`, `connection_error`, `invalid_response`, `startup_failed`), start/stop cycles with cleanup checks against simulated Docker, the startup failure taxonomy (`model_not_found`, `invalid_configuration`, `out_of_memory`, `startup_timeout`, `container_exited`, `interrupted`), mocked telemetry cases per vendor, stable device positions on failure, and the coverage gates.

**Provable only on real hardware (open, see the evidence list):**

1. Start/stop: 10 cycles per active backend with an unchanged reference-model identity within its cycles, 10/10 without orphaned containers.

   ```bash
   python scripts/smoke_all_backends.py --backends llama_cpp ollama vllm --cycles 10 --device gpu --output results/qualification/cycles
   ```

   The smoke test uses backend-specific default models. For acceptance, retain
   model revision/hash, image digest, and actual GPU API alongside the artifacts;
   a green smoke alone establishes neither version pins nor CUDA. Use a distinct
   output directory for every new run to preserve earlier evidence.

2. Ollama: at least two pinned server versions, context sizes 1024/4096/8192, CPU-only and NVIDIA GPU; a prompt that would otherwise be silently truncated must never count as verified.
3. Telemetry: real traces for each available NVIDIA/AMD/Intel device. Missing vendors are entered explicitly as "not tested".
4. Linux and Windows (Docker Desktop/WSL2) following the CI matrix Python 3.10/3.12/3.14.
5. 8-hour soak on the reference hardware:

   ```bash
   # benchmark.yaml: soak.duration_long_seconds: 28800
   llmbench run --config benchmark.yaml --hardware both --duration long
   ```

   Check: no abort, no throttling warning, telemetry completeness (`sample_completeness`) and sampler overhead (`sampling`) in the result, and no owned containers left afterwards.

6. Five independent repeats of an identical reference workload, keeping each
   result and reporting the spread as required by #124. Do not invent an absolute
   tokens/s threshold across different engines.

**TGI (#120):** Decided: TGI is being discontinued and replaced by SGLang (see #167). The hardware validation from #120 is therefore dropped for 1.7.0. Background: the validation record [2026-10-23-gpu.md](2026-10-23-gpu.md) documents that TGI 3.3.6 crashes during GPU warmup on an RTX 5070. Until it is removed (planned for 1.8.0), TGI is not considered validated.

### Limitations found during qualification

- **Soak with container backends:** With Ollama the soak fails (`llama-server wurde nicht bereit`), with llama.cpp it runs. Cause according to the architecture contract: container backends manage exactly one container (capability `multi_model`). The soak is now skipped with a clear message for them and is only proven for llama.cpp.
- **CUDA not proven:** llama.cpp ran as a Vulkan build; a CUDA proof is still missing.
- **Efficiency values of CPU profiles** only reflect the measured GPU power (scope `gpu:0`) because CPU power is not available. They are not comparable with GPU profiles.
- **Sampler:** One measurement takes 88 ms on average (about 15% of the interval), so the real interval is about 0.59 s.
